# Three hypotheses died to a file nobody opened — read the source before you fund the experiment

**2026-08-15.** One session, one dead sensor, four competing explanations. All four were refuted.
**None of them was refuted by an experiment.** Each died to a file that already existed and that
took under a minute to read.

## Symptom

An analog input read a constant, non-varying value at the noise floor. Over one run the conductor
formed and dispatched work on three explanations in sequence:

1. *"The DSP stage downstream is gating the signal to zero."* Built on reading the device's own
   reported config, which listed that stage's parameters as active.
2. *"Firmware is reading the wrong physical leg of the sensor."* Built on the operator saying which
   pins the sensor spanned.
3. *"The chip's internal bias generator is disabled — enable it."* Built on a code comment that
   asserted bias was supplied externally.

A fourth, inherited from a config-file comment, held that the DSP stage was architecturally welded
to one bus and could not be used on this board.

## What actually happened

- **(1) died to a Kconfig file.** The board compiles that DSP stage *out entirely*. The device had
  been advertising configuration for a stage it does not build — a lying instrument, and the direct
  cause of the wrong hypothesis. One `grep` of the board's config overlay would have killed it.
- **(2) died to a maintained wiki page.** The per-unit hardware record stated which pins carry the
  hot legs. They were exactly the pins the firmware already selects. The proposed "fix" would have
  switched to the ground-return legs — strictly worse, and it would have produced a confident wrong
  reading. It did not run **only because the agent refused to write a register whose encoding it
  could not source.**
- **(3) died to a datasheet fact already written into the project's own hardware notes**: the part
  has no such pin. There was no knob to turn.
- **(4) died to a source read.** The "welded to one bus" claim was false: the entire coupling was
  **one line**. The operator had asserted this on architectural grounds and was right.

## The rule

**Before dispatching an experiment, read the authoritative source for the premise the experiment
tests.** Not the code that consumes the fact, not a comment near it, not the device's own report of
itself — the source of record: the config that decides what is compiled, the maintained hardware
page, the datasheet.

The discriminator, and it is cheap: **"if this hypothesis is wrong, which existing file already
says so?"** If you can name the file, open it. It is usually one command, and it is always cheaper
than a build-flash-measure cycle plus the wrong conclusion at the end of it.

## Why it generalises

Three properties made these hypotheses feel well-founded when they were not, and none is specific
to hardware:

- **A system's self-report is not a source.** A device reporting settings for a stage it does not
  compile is the same class as a service reporting a feature flag it never reads, or an ORM
  reporting a column the migration dropped. The report is generated by code that does not know
  what it is describing.
- **A comment is an assertion by someone who is gone.** Two of the four rested on comments — one
  asserting external bias, one asserting an architectural constraint. Both were wrong, and both had
  been read and believed by several readers before.
- **The evidence you have is the evidence that is convenient**, and a live system is always the
  most convenient thing to query. That biases every investigation toward hypotheses phrased in
  terms of runtime state, and away from the compile-time and physical facts that actually bound it.

## The corollary worth keeping

**An agent that refuses to act on an unsourced value is doing the job.** Twice in this session a
delegate reported *"I cannot establish this encoding from a real source, so I did not write it"* —
after a genuine search. Both refusals were correct, and the second one prevented a change that
would have made things worse while looking like progress. A prior run on the same component had
taken a value from a driver header instead of the datasheet and selected a **reserved** state.

Brief delegates so that this is the expected outcome, not a failure: *"if you cannot establish it
from a real source, say so and do not write it."* Then treat the refusal as a result, not a
non-answer.
